# Forge 1.20.1 Medieval RPG Modpack Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce the `test-1.20.1` client to a stable dark-fantasy medieval RPG set derived from the 1.21.1 reference pack while preserving every quarantined JAR for restoration.

**Architecture:** PowerShell tooling reads mod metadata directly from JAR archives, compares active Forge 1.20.1 mod IDs with the NeoForge 1.21.1 reference, closes mandatory dependencies, and emits a deterministic cleanup plan. A separate apply command performs verified moves into a timestamped quarantine and writes SHA-256 manifests; validation never deletes files and runtime checkpoints remain explicit.

**Tech Stack:** Windows PowerShell 5.1, .NET `System.IO.Compression`, Forge/NeoForge TOML metadata, JSON, CSV, SHA-256, Minecraft Forge 1.20.1 client logs.

- Exclude Tensura and its bridges from the Forge 1.20.1 selection even if they appear in the 1.21.1 reference.

- Do not apply a plan containing an unresolved mandatory dependency or an unresolved same-mod-ID conflict.

- The 120–150 JAR target is advisory; dependency correctness and runtime stability take priority.
