# Magic Tree Visual Atlas Design

## Goal

Improve the existing unified magic tree so it feels centered, ceremonial, and immediately readable.

The target is not a gameplay redesign. The target is a visual composition upgrade of the current Puffish-based tree so the player sees:

- a strong central core
- a composition that is actually centered on screen
- branches with recognizable silhouettes
- cleaner spacing and fewer overlaps
- a stronger sense of magical prestige

## Scope

This spec covers only the visual structure generated by `PuffishMagicTreeBuilder`.

It includes:

- node positioning rules
- branch composition rules
- visual hierarchy rules
- overlap-reduction rules
- centering rules
- branch identity rules

It does not include:

- gameplay changes
- unlock-rule changes
- cost changes
- new magic nodes
- new UI framework
- custom replacement screen for Puffish

## Current Problems

The current tree has several readability issues:

1. The whole composition feels offset instead of intentionally centered.
2. The center node exists, but does not dominate enough to anchor the eye.
3. Some branches read like dense technical clusters instead of meaningful magical schools.
4. Signature spells can feel scattered rather than arranged around a clear branch spine.
5. The global composition has noise and local overlaps that weaken branch identity.

The current layout already has useful foundations:

- radial branch placement
- spell-icon usage from real mod assets
- size variation between node types
- anti-overlap relaxation

The new design should keep those strengths and replace the weak composition.

## Visual Direction

The tree should evolve from a generic radial graph into a `magical atlas`.

The intended feeling is:

- ancient
- deliberate
- prestigious
- symmetrical at macro scale
- expressive at branch scale

The player should first read the tree in this order:

1. the central nucleus
2. the major branch sectors
3. the branch spines
4. the signature spell constellations

The tree should not look like a data visualization first. It should look like a magical progression map first.

## Composition Rules

### 1. True Centering

The composition must be centered by visual mass, not just by minimum left padding.

The current logic recenters primarily from the left boundary. That is insufficient because a tree can still appear globally shifted if one hemisphere carries more visual mass.

The new centering model should:

- compute the bounding box of all visible nodes after branch placement and relaxation
- compute the bounding-box center
- shift the entire constellation so its center aligns with the intended viewport center
- preserve a minimum safe margin from the viewport edges

If exact viewport dimensions are unavailable at generation time, the layout should still use a stable virtual canvas center that is itself symmetric, so left/right balance remains intentional.

### 2. Sacred Nucleus

`common/foundation/arcane_focus` becomes the visual throne of the tree.

Rules:

- it must remain the geometric anchor of the composition
- it must be the largest node in the tree
- it must have a larger empty radius around it than any other node
- nearby common foundation nodes must support it rather than compete with it

The center should feel isolated enough that branches visibly emerge from it.

### 3. Branch Spine Model

Each school must read as a structured branch rather than a cloud of disconnected points.

Every branch should be composed as:

- one opener
- one readable outward progression spine through tier nodes
- one or more spell clusters attached to that spine

The spine is the authoritative shape of the branch.
Signature spells are subordinate satellites around it.

### 4. Macro Balance

The full tree should remain approximately circular or oval at global scale, but not mechanically uniform.

Balance goals:

- no dominant dead mass on only one side
- no branch cluster should visually crush its opposite side
- advanced schools can feel rarer, but still must contribute to a stable silhouette

The final impression should be “centered magical mandala”, not “graph pushed to one side”.

## Branch Identity Rules

Each school should have a distinctive silhouette while still living inside the same atlas.

### Fire

Desired feeling:

- violent
- ascending
- flaring outward

Shape rules:

- fan-like spread
- slightly aggressive diagonal
- tighter inner structure, sharper outer spread

### Water

Desired feeling:

- fluid
- descending
- wave-like

Shape rules:

- smoother arc than fire
- more curved drift along its outer spell clusters
- less jagged spacing

### Air

Desired feeling:

- open
- light
- lifted

Shape rules:

- broad arc
- generous spacing
- fewer cramped local clusters

### Earth

Desired feeling:

- compact
- rooted
- heavy

Shape rules:

- denser silhouette
- shorter lateral spread
- strongest sense of structural mass

### Holy

Desired feeling:

- elevated
- rare
- pure

Shape rules:

- cleaner and more ordered than chaotic branches
- less noise, more ceremonial spacing

### Blood

Desired feeling:

- invasive
- asymmetrical
- dangerous

Shape rules:

- slightly more predatory silhouette
- can tolerate sharper offsets than holy

### Ender

Desired feeling:

- unstable
- strange
- spatially bent

Shape rules:

- more unusual branching rhythm
- slightly uncanny spacing without becoming messy

### Evocation

Desired feeling:

- tactical
- engineered
- controlled

Shape rules:

- clean branch spine
- disciplined cluster layout

### Eldritch

Desired feeling:

- obscure
- deep
- otherworldly

Shape rules:

- remote-looking silhouette
- slightly alien curvature
- should feel like a late and dangerous school

## Node Hierarchy Rules

The current size differences must be made more dramatic.

The tree should use four obvious visual tiers:

1. Central nucleus
2. Branch openers
3. Tier progression nodes
4. Signature spell nodes

Target hierarchy:

- center: visually dominant, unmistakable
- openers: clearly important landmarks
- tier nodes: visible progression checkpoints
- signature nodes: numerous but subordinate

The player must never confuse “major progression landmark” with “ordinary spell node”.

## Empty Space Rules

Empty space is a design tool, not wasted area.

The improved tree should deliberately preserve:

- a breathing halo around the center
- enough separation between neighboring school sectors
- enough local room inside each branch to avoid visual mud

The system should prefer fewer, cleaner cluster lanes over overfilling available space.

## Overlap and Spacing Rules

The existing relaxation pass should remain, but with stricter artistic intent.

Rules:

- branch spines should remain stable and mostly fixed
- signature nodes are the primary movable elements during relaxation
- relaxation should protect school silhouette before maximizing raw compactness
- center, opener, and tier nodes should not drift enough to weaken the designed branch shape

The algorithm should prioritize:

1. preserving the planned branch silhouette
2. avoiding overlap
3. keeping spells close enough to read as belonging to their branch

## Connection Readability

Connection readability should improve indirectly through better geometry.

The layout should aim for:

- clearer parent-child flow
- less ambiguous crossing
- reduced visual clutter near the center

The design should avoid large numbers of branch links that visually collapse into one noisy area.

## Implementation Direction

This redesign should stay inside `PuffishMagicTreeBuilder` rather than introducing a new UI stack.

Primary implementation areas:

- revise branch angles and branch-sector zoning
- revise opener and tier radii
- revise signature cluster generation rules
- strengthen node-size scaling
- replace the current left-biased recentering with true composition centering
- tune relaxation so only movable spell nodes absorb most spacing corrections

The implementation should remain deterministic.
The same input tree should generate the same visual result.

## Acceptance Criteria

The redesign is successful when all of the following are true:

1. The tree is visually centered when opened in the Puffish UI.
2. The central node is clearly the dominant anchor.
3. Each major school has a recognizable silhouette at first glance.
4. The tree is easier to parse from center to branch to spell.
5. Signature spell overlaps are reduced without flattening school identity.
6. Real spell icons from the mods remain in use.
7. No gameplay logic changes are introduced as part of the visual pass.

## Files Expected To Change

- `src/main/java/tong/statmod/integration/puffish/PuffishMagicTreeBuilder.java`
- possibly generated Puffish category resource outputs if the layout exporter is re-run

## Risks

1. Over-correcting centering can make some branches hit viewport edges earlier.
2. Strong silhouette rules can conflict with anti-overlap logic if relaxation is too aggressive.
3. Increasing size hierarchy too much can make some icon clusters feel too small unless spacing also improves.

These risks are acceptable and should be handled by iterative tuning inside the existing generator.
