# Forge 1.20.1 Medieval RPG Modpack Cleanup Design

**Date:** 2026-07-15  
**Client:** `test-1.20.1`  
**Reference:** NeoForge 1.21.1 mod set in `libs/`  
**Theme:** dark-fantasy medieval RPG  
**Status:** approved design

## 1. Goal

Reduce the Forge 1.20.1 client from approximately 249 active JARs and 1.46 GiB
to a coherent, stable dark-fantasy medieval RPG pack. Preserve STAT Mod, Epic
Fight, Iron's Spells, medieval combat, fantasy magic, bosses, exploration,
quests, economy, and all libraries required by the retained mods.

The first stable target is 120–150 active JARs. This is a target range rather
than a hard cap: dependency correctness and runtime stability take priority.

## 2. Safety model

No JAR is deleted. Removed candidates are moved into a timestamped quarantine
outside the active `mods/` directory. Every move is recorded in a manifest with:

- original filename and SHA-256;
- byte size;
- detected mod identifiers;
- classification;
- reason for quarantine;
- source and destination paths.

Restoration consists of moving a recorded file back to `mods/`. The active
STAT Mod JAR is protected from quarantine.

## 3. Selection model

Selection uses a whitelist derived from the working 1.21.1 reference pack.
Filename similarity is supporting evidence only. Mod IDs and mandatory
dependencies from `META-INF/mods.toml`, `META-INF/neoforge.mods.toml`, or
equivalent metadata determine identity and dependency closure.

An active Forge 1.20.1 JAR is retained when at least one condition applies:

1. it is the 1.20.1 equivalent of a selected 1.21.1 reference mod;
2. it is a mandatory dependency of another retained JAR;
3. it is an explicitly retained 1.20.1-only dark-fantasy addon;
4. it is an optimization or administration component required for the client;
5. it is STAT Mod.

Optional dependencies are not automatically retained. A library is retained
only while at least one active selected mod needs it.

## 4. Retained identity

### 4.1 Medieval combat

Retain Epic Fight and the coherent medieval combat set, including Epic Knights,
Simply Swords, Weapons of Miracles, Dual Axes, lock-on, dodge/parry components,
and their required libraries. Duplicate bridges providing the same mod ID or
the same integration are reduced to one compatible implementation.

### 4.2 Dark-fantasy magic

Retain Iron's Spells and compatible medieval-fantasy addons, Ice and Fire
Spellbooks, and their required libraries. Addons with missing content,
unresolved mandatory dependencies, or fatal datapack errors begin in
quarantine and may return only through the staged reintroduction process.

### 4.3 World, bosses, and creatures

Retain the coherent reference set: Cataclysm, Mowzie's Mobs, Ice and Fire, Born
in Chaos, Alex's Mobs, Biomes O' Plenty, medieval bosses, dungeons, structures,
and required world-generation libraries.

### 4.4 RPG systems

Retain Apotheosis, Puffish progression, the necessary FTB quest/team stack,
the selected SDM economy stack, Bountiful, Farmer's Delight, Waystones, Lootr,
and STAT Mod.

### 4.5 Technical foundation

Retain one compatible version of each required library and proven client/server
optimization. Connector and Fabric payloads are retained only if a selected
mod has no native Forge replacement and passes the runtime validation stages.

## 5. Initial quarantine policy

The initial quarantine includes:

- modern firearms and unrelated modern combat, including TACZ and CGM;
- industrial/technology systems absent from the reference identity, including
  Create and its addons;
- unrelated universes such as Arknights, Slugterra, Project Babylon, and
  similar content;
- duplicate implementations or concurrent versions of the same mod ID;
- orphan libraries after dependency closure;
- addons whose mandatory dependencies are absent;
- mods responsible for confirmed fatal errors.

TCR Bosses 1.1.12 remains quarantined because it references the removed
`SkyGolem` class while the installed BattleTowers uses `BTSkyGolem`.
Galosphere 1.5.2 remains quarantined because Create 6.0.8 supplies fatal
recipes whose result is the nonexistent `galosphere:silver_ingot`.

## 6. Validation stages

The cleaned set is accepted only after these stages pass in order:

1. Forge reaches the main menu without a new crash report.
2. A new single-player world can be created and loaded.
3. The player remains in the world for several minutes while chunks generate.
4. STAT Mod commands return player statistics.
5. A standard Epic Fight melee action works.
6. A standard Iron's Spells cast works.

Logs are inspected after every stage for fatal errors, missing mandatory
dependencies, registry failures, and datapack failures. Nonfatal warnings are
recorded separately and are not silently treated as success.

## 7. Staged reintroduction

After the base set passes all validation stages, quarantined dark-fantasy extras
are reintroduced in small, named batches:

1. Iron's Spells addons;
2. Epic Fight addons;
3. other medieval dark-fantasy content.

Each batch repeats world creation, STAT Mod, combat, and spell smoke tests. If a
batch fails, only that batch is returned to quarantine and then narrowed by
binary isolation. A failed addon is never allowed to destabilize the validated
base set.

## 8. Deliverables

- a cleaned active `mods/` directory;
- a timestamped reversible quarantine;
- CSV manifests for retained and quarantined JARs;
- a dependency and duplicate audit;
- a validation report containing each launch result and crash cause;
- no source-code changes to STAT Mod unless runtime evidence identifies a STAT
  Mod defect.

## 9. Non-goals

- deleting downloaded JARs;
- reproducing every 1.21.1 feature exactly on Forge 1.20.1;
- retaining modern firearms, industrial technology, or unrelated universes;
- claiming an addon compatible before it passes the staged runtime tests;
- fixing third-party mod internals as part of the initial cleanup.
